This repository documents a 30-day, hands-on journey from basic navigation to remotely operating a server over SSH. Each day covers ten commands and their derivatives (300 in total), grouped into six phases where every phase builds on the last, and each phase ends in a checkpoint drill that must be completed before moving on. Every command is typed by hand, run on a real system, explained in my own words, and backed by evidence, so the repo shows not just that I know a command exists but that I can combine commands to solve realistic operational problems.

## Real problems this repo works through

Each drill is a small, realistic sysadmin task, not a command recital. These are the operational situations the 30 days are built around:

| Situation | What I do about it | Key commands | Day |
|---|---|---|---|
| A disk is filling up and nobody knows why | Locate oversized files, quantify usage per directory, check remaining space | `find -size`, `du -sh`, `df -h` | [4](./day-04-filesystem-search/) |
| A script "works for me" but fails for the service account | Read, reason about, and correct permission bits and default `umask` | `ls -l`, `chmod`, `umask`, `stat` | [6](./day-06-permissions/) |
| A team needs a shared folder without everyone owning everything | Group-inherited directories with SGID, ACLs for exceptions | `chown`, `chmod g+s`, `setfacl`, `getfacl` | [7](./day-07-ownership/) |
| Is anything on this box escalating privileges it should not? | System-wide SUID audit; review of what my own account may run via sudo | `find / -perm /4000`, `sudo -l`, `visudo` | [7](./day-07-ownership/), [8](./day-08-privilege-escalation/) |
| Verify a download, protect a file, shrink the attack surface | Checksums, immutable files, firewall opened only for 22 and 443 | `sha256sum`, `chattr +i`, `ufw` | [9](./day-09-integrity-firewall/) |
| Who has been on this server, and who should not have been? | Login forensics: recent, current, never-logged-in, failed attempts | `last`, `lastlog`, `lastb`, `w`, `who` | [10](./day-10-security-audit-checkpoint/) |
| Onboard a new engineer in one documented sequence | Create the account, groups and password, then install their toolchain | `useradd`, `usermod`, `gpasswd`, `apt` | [11-15](./day-15-provisioning-checkpoint/) |
| Same job on a different distribution family | Compare `apt`/`dpkg` and `dnf`/`rpm` workflows side by side | `apt`, `dnf`, `rpm -qa` | [13](./day-13-apt-package-management/), [14](./day-14-dnf-yum/) |
| Make a shell reproducible instead of tweaking it by hand | Session vs persistent environment, `PATH`, aliases | `export`, `source`, `~/.bashrc` | [16](./day-16-environment-variables/), [17](./day-17-shell-configuration/) |
| Edit a config on a server that has no GUI | Modal editing, search and bulk replace in Vim | `vim`, `:%s/old/new/g` | [18](./day-18-vim-fundamentals/), [19](./day-19-vim-search-replace/) |
| Pull the signal out of a raw log file | One chained pipeline: filter, extract, sort, de-duplicate | `grep`, `awk`, `sed`, `sort`, `uniq` | [20](./day-20-text-processing-checkpoint/) |
| A process is hung, greedy, or must outlive my SSH session | Find it, signal it, background it, detach it | `ps`, `top`, `kill`, `nohup`, `disown` | [21](./day-21-viewing-processes/), [22](./day-22-process-signals/) |
| A service is down at 2 a.m. | Status, failed units, error-level logs, live log follow | `systemctl`, `journalctl -p err` | [23](./day-23-systemctl-basics/), [24](./day-24-service-logs/) |
| Give the on-call engineer a one-screen picture of a server | Uptime, memory, key services and cron jobs in a single view | `uptime`, `free -h`, `systemctl status`, `crontab -l` | [25](./day-25-operational-snapshot-checkpoint/) |
| Reach and move files between machines safely | Key-based SSH, `scp`/`rsync`, sshd hardening | `ssh-keygen`, `ssh-copy-id`, `rsync` | [27](./day-27-ssh-file-transfer/) |
| Stop doing the same check by hand | Bash scripts, functions with arguments, cron, `trap`, `logger` | `bash`, `cron`, `trap`, `logger` | [28](./day-28-bash-scripting/), [29](./day-29-functions-automation/) |
| Ship a change to a remote server and prove it is healthy | Capstone: deploy over SSH with correct ownership and permissions, restart, verify, and log the whole run | `ssh`, `scp`, `chown`, `systemctl`, `journalctl` | [30](./day-30-capstone/) |

### Why this matters for cloud, DevOps and MLOps work

Cloud virtual machines, container images, CI runners and GPU training servers are overwhelmingly Linux machines reached over SSH and managed through the shell. The skills practised here (least-privilege permissions, service and log triage, scripted repeatable checks, safe remote deployment) are the day-to-day foundation under infrastructure-as-code, container debugging and ML pipeline operations.

## Working standards

- **Typed, not pasted.** Every command is typed by hand on a real Linux system.
- **Own words.** Explanations are written by me, not copied from man pages or the brief.
- **One commit per day, never backdated.** Commit messages follow `Day N: <topic>`; the history is the audit trail.
- **No secrets.** No real passwords, private keys, tokens, internal IPs or client data appear in this repo or in the write-ups; placeholders are used throughout.
- **Least privilege by default.** Drills that touch security (permissions, sudo, firewall, SSH) are done deliberately and reverted or documented.

**Lab environment:** Ubuntu 24.04LTS Ubuntu Linux
